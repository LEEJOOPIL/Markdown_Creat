# 기술 스택 (tech.md)

> 이 문서는 아직 코드가 작성되지 않은 신규 프로젝트를 위한 **기술 스택 권장안**입니다. 인터뷰에서 확인된 요구사항(Python 기반, 템플릿 기반 마크다운 자동 생성)을 바탕으로 작성되었습니다.

## 주 언어

- **Python** (인터뷰에서 확정된 기술 스택)
  - 권장 최소 버전: **Python 3.10 이상** (최신 타입 힌트 문법, `match` 구문 등 활용 가능)
  - 별도의 컴파일/빌드 단계가 필요 없는 인터프리터 언어로, 간단한 CLI/라이브러리 형태의 배포에 적합

## 템플릿 엔진 (핵심 기술 선택)

### 1순위 권장: Jinja2

- 템플릿 기반 문서 자동 생성이라는 핵심 요구사항에 가장 적합한 표준 템플릿 엔진
- 조건문(`{% if %}`), 반복문(`{% for %}`), 필터, 템플릿 상속 등 강력한 표현력을 제공하여 보고서/회의록처럼 구조가 있는 문서를 유연하게 생성 가능
- Flask, Ansible 등 다수의 파이썬 생태계 도구에서 사실상 표준으로 사용되어 커뮤니티 자료와 안정성이 풍부함
- 설치: `pip install jinja2` (단일 의존성 추가로 도입 부담이 낮음)

### 대안: Python 내장 `string.Template`

- 외부 의존성 없이 표준 라이브러리만으로 간단한 치환(`$변수` 또는 `${변수}`)이 가능한 경량 대안
- 조건문/반복문 등 복잡한 로직이 필요 없는 매우 단순한 템플릿(단순 변수 치환 수준)에는 충분
- 프로젝트 초기 프로토타입 단계나 의존성을 최소화하고 싶은 경우 고려 가능하나, 보고서/회의록처럼 반복 구조가 필요한 문서에는 표현력이 부족할 수 있음

**권장 방향**: 초기 프로토타입은 `string.Template`로 시작해볼 수도 있지만, 실제 "정해진 템플릿에 맞춰 문서를 생성"하는 요구사항(반복 항목, 조건부 섹션 등)을 고려하면 **Jinja2를 기본 채택**하는 것을 권장합니다.

## 개발 환경 요구사항

- **Python 버전**: 3.10 이상 (3.11/3.12도 호환 가능)
- **패키징 도구**: `pyproject.toml` 기반 (PEP 621 표준) — `setuptools`, `hatchling`, 또는 `poetry` 중 택 1
- **의존성 관리**: 최소 의존성 원칙 유지 (Jinja2 + 필요 시 YAML 파서인 `PyYAML` 정도)
- **가상환경**: `venv` 또는 `uv`/`poetry` 등으로 격리된 개발 환경 구성 권장
- **테스트 프레임워크**: `pytest` (TRUST 5 품질 기준의 Tested 원칙 충족)
- **린트/포맷터**: `ruff` (린트), `black` (포맷) — MoAI-ADK 표준 Python 툴체인과 일치

## 빌드/배포 복잡도

- 이 프로젝트는 **단순한 Python CLI/라이브러리** 수준의 배포만 필요하며, 별도의 인프라(서버, 컨테이너, 클라우드 배포 등)를 요구하지 않습니다.
- 배포 형태(예정):
  - 로컬 CLI 도구로 사용 (`python -m markdown_creat` 또는 `pip install -e .` 후 커맨드 실행)
  - 필요 시 PyPI 패키지로 배포하여 `pip install markdown-creat` 형태로 설치 가능하게 확장
- CI/CD는 GitHub Actions 등을 활용한 **린트 + 테스트** 수준이면 충분하며, 별도의 배포 파이프라인(도커, 서버 배포 등)은 현재 스코프에서 불필요합니다.
